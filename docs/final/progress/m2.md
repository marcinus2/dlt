## Decisions / deviations from plan

- **Additions to the spec §5.2 types** (needed by the §14 gaps):
  - `AppState.tuning` + events `TUNE_START` / `TUNE_STOP` (G6–G8).
  - `CONFIG_CHANGED` carries `valid`, stored as `AppState.configValid`. It drives the "draft valid" guard on SAVE.
  - `camera.start` / `engine.start` effects take an optional `draft: true`. Tuning uses the draft settings, everything else the saved ones (G8).
  - `CameraInfo` is a named type (the return of `FrameSource.start()`).
  - `CameraPort = FrameSource & { configure(settings) }`, because `FrameSource.start()` takes no settings.
- **New gap, G13:** `CAMERA_LOST` is also handled on Get Ready and while tuning. The camera goes to the error state and the engine and camera stop. The spec only lists it for Session.
- **Dialogs block user events:** with a dialog open, only `CONFIRM` / `CANCEL` and system events (`PASS`, `ARMED`, camera, visibility) get through. An auto-pause under a dialog keeps the dialog.
- **Stale camera events on Paused are ignored.** The plan's "Paused | CAMERA_ERROR" row is covered by G2 in Session.
- **Get Ready `APP_HIDDEN` always turns the camera off, even from an error.** So `APP_VISIBLE` retries it, e.g. after the user allowed the camera in system settings.
- **Screen transitions animate on enter only** (fade + 8 px slide in the direction of travel), with no `AnimatePresence` exit. An exiting screen would re-render against torn state (e.g. `session = null`), and the 300 ms tap guard stays simple. Session and Paused are one view, so there is no transition between them and the list scroll position is kept.
- **Tap guard:** primary buttons are `aria-disabled` for 300 ms after mount and ignore a second tap within 300 ms. Playwright's actionability waits for it, so e2e needs no sleeps around transitions. Android also gets `vibrate(20)`.
- **List "layout animation"** uses WAAPI on the `<ol>` (translateY one row, new row fades in) instead of Motion `layout` on up to 500 rows. No bundle cost; skipped under reduced motion.
- **Sim controls** are a strip under the top menu, not a floating panel: the floating version covered the status line. On wide or landscape screens the strip sits inline in the header, so no height is lost.
- **Preview fit** uses a `ResizeObserver`, not container units. Container height units resolved to 0 inside the flex layout in Chromium, so the preview was invisible.
- **Hero digits** are `clamp(4.5rem, 24cqi, 12rem)` (cqi of the hero column) instead of `24vw`, so the two-column layout doesn't clip them. A `short:` variant (`max-height: 500px`) tightens landscape phones; there the digits are `min(24cqi, 20dvh)`.
- **Get Ready START** uses a compact hero size, `clamp(200px, min(56vw, 30dvh), 260px)`, so preview, health line and START fit one phone screen. Welcome keeps `min(72vw, 320px)`.
- The placeholder camera's label is drawn pre-mirrored for the front camera, so it reads correctly after the UI mirror.
- **WebKit project** runs `smoke` + `gallery` only (layout + axe, as plan §0 says); the flows run on Chromium.
- **Fixes from axe:** dialog buttons use 20 px bold (white on `--danger` is 4.2:1, so it needs large text); the lap-history scroll container is focusable (`scrollable-region-focusable`).
- **URL flags** (read once): `?cam=fake` (placeholder camera), `?auto=0`, `?lap=<s>`, `?debug=1` (logs ignored events and sim cues), `?gallery`, `?state=<id>`.
- **Placeholders that later milestones wire up** (visible only through UI flags / gallery): install link and iOS hint (M9), update toast (M9), "tap to enable sound" (M6), wake-lock banner (M8), device picker shown as a disabled "Automatic" (M7), Test & calibrate and Diagnostics cards (M7). The permission card always says "blocked"; the blocked vs not-yet-asked text comes with `permissions.query` in M8.
- `motion.tsx` instead of `motion.ts` (it exports the provider component).
- `npm install` pruned the unused `esbuild` entries from the lockfile (Vite 8 uses Rolldown/Oxc).
