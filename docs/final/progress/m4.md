## Device checklist (M4 exit)

On the branch deploy or after merge, open `…/?debug=engine` on the phone:

1. **Start camera** → HUD `fps` ≈ 30, `phase armed` after ~1.5 s; wave a hand over the camera → ratio moves, MOTION START/END in the log.
2. Reference Samsung at defaults: HUD `fps ≥ 27`, `ms/frame p95 ≤ 15`. Note `delivered`, `roi`/`diff` ms and `t:` (expect `captureTime` on Android).
3. iPhone (Safari + installed) and desktop: camera starts; note `fps`, `t:` and `exposure` (expect "not supported" on iOS).
4. **Stop** → the camera indicator goes off; HUD `fps` drops to 0.
5. Optional parity on a real clip: replay the same video in `/poc/` and `?debug=engine`, export both events CSVs, compare.

## Decisions / deviations from plan

- **Debug page flag is `?debug=engine`, not `?debug=1`.** `?debug=1` already means "machine log + Diagnostics section in Configuration" (D4, M2). The standalone page is an M4/M5 tool; Configuration Diagnostics replace it in M7.
- **`resetGapMs` is applied by the engine, not the source.** It's a detection setting (live-tunable) and the source only knows camera settings. Sources set `gapReset` for discontinuities they see (loop/seek); the engine ORs in `t − lastT > resetGapMs`.
- **No per-frame allocation in the hot path:** `detector.update()` returns a shared frozen empty array when there are no events; the analyzer returns one reused result; the engine emits one reused `MotionSample` and the frame loop one reused `FrameMeta` (listeners copy what they keep). `getImageData` still allocates (no read-into API, as in the PoC).
- **Engine phase:** `IDLE`/`CANDIDATE` → `armed`, `MOTION` (incl. a suppressed one) → `motion`. As with the sim, `armed` is emitted after every pass too; the reducer already ignores a repeated `ARMED`.
- **Order per frame:** `event`s → `phase` → `pass` → `sample`; the run id is re-checked after every listener, so a listener may `stop()` or `reset()` mid-frame.
- **`ms/frame`** measures analyzer + detector (the PoC's total also included its canvas preview, which v1 doesn't have).
- **Synthetic start latency:** the detected start is up to ~100 ms after the blob enters at 60 fps (the entering edge must reach `startRatio`). Same physics as the PoC; the test checks lap gaps exact to one frame and latency ≤ 150 ms instead.
- **`toCameraError` moved** to `engine/camera-error.ts` (pure), re-exported from `app/effects.ts`.
- **CameraSource "any camera" step** also runs after `NotFoundError` for the facing camera; the frame loop only runs while someone listens.
- **FileSource `onEnded`** fires on a playback error (`kind: 'unknown'`).
- **Golden fixtures** live in `app/test/fixtures/` (README with expected pass counts); M0 field CSVs go to `field/` and need an entry in `EXPECTED` in `replay.test.ts`.
